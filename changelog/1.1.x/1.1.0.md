# 1.1.0 — 2026-09-08

## Added

- Streamable HTTP configuration with static headers alongside stdio entries, validated before connecting. ([#8](https://github.com/cyanheads/mcp-reporter/issues/8))
- `--protocol-era legacy|auto|2026-07-28` and matching library options; legacy remains the default without a discovery probe. ([#6](https://github.com/cyanheads/mcp-reporter/issues/6))
- Prompt enumeration, descriptor titles, annotations, output schemas, icons and extension metadata, plus server identity, instructions and the negotiated protocol. Advertisements are retained without certifying tool callability. ([#4](https://github.com/cyanheads/mcp-reporter/issues/4), [#5](https://github.com/cyanheads/mcp-reporter/issues/5), [#7](https://github.com/cyanheads/mcp-reporter/issues/7))
- Deterministic in-memory, stdio and HTTP fixtures; local lint/typecheck/test gates and compiled Node package checks. ([#13](https://github.com/cyanheads/mcp-reporter/issues/13))
- Project workflows, contribution/security guidance, synthetic report generation and versioned changelog tooling.

## Changed

- **Breaking:** compiled output is ESM and requires Node.js 22.12 or newer for the updated dependency set. The SDK migration itself does not require ESM. See the [upgrade guide](../../docs/upgrading.md) for imports, reporting and development changes. ([#12](https://github.com/cyanheads/mcp-reporter/issues/12))
- Reports use portable Markdown tables and collapsible definitions instead of CSS-dependent cards. Consumers parsing the previous Markdown structure must adapt. ([#10](https://github.com/cyanheads/mcp-reporter/issues/10))
- Library progress is opt-in; CLI progress uses stderr. Bun runs development scripts and maintains the lockfile; npm and GitHub publishing use local release gates.

## Removed

- Unused report formatters, empty decorative sections and the GitHub Actions publishing workflow.
- Generated local reports from version control and package output; `docs/example-report.md` provides a synthetic example.

## Fixed

- All four capability lists follow every cursor, including empty strings. Repeated cursors, page bounds and later failures retain collected entries with explicit incomplete status. Unadvertised, successful empty and failed lists remain distinct. ([#2](https://github.com/cyanheads/mcp-reporter/issues/2), [#3](https://github.com/cyanheads/mcp-reporter/issues/3))
- Rendering options now control input schemas, server metadata and caller-supplied examples; negative CLI flags disable them. Connection duration includes valid zero-millisecond measurements. ([#11](https://github.com/cyanheads/mcp-reporter/issues/11))
- Created transports are closed after startup and report-write failures, and subsequent runs collect fresh results.
- CLI and MCP handshake versions use package metadata; direct executable failures retain a nonzero exit status.

## Security

- Remove configured env/argument dumps and raw peer/transport errors from diagnostics. Reports omit launch arguments, header values and credential-bearing URL components; child stderr is suppressed. ([#9](https://github.com/cyanheads/mcp-reporter/issues/9))
- Escape server-supplied Markdown/HTML delimiters and size JSON fences to preserve report structure. Remote icons remain metadata.
