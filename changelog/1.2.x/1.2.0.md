# 1.2.0 — 2026-11-15

## Added

- **Concurrent collection** — up to four servers are collected at once, and each connection closes as soon as its lists are read. One slow or stalled server no longer delays the rest; the report keeps configuration order.
- **Same-origin HTTP redirects** — an HTTP endpoint may redirect within its own origin (for example `/mcp` to `/mcp/`). A redirect to another origin, or one that changes the request method, is reported as `HTTP <status> redirect not followed`, and configured headers are never sent to the other origin.
- **Verbatim descriptions** — each tool, resource, resource template and prompt description appears in its own fenced `text` section, and server instructions are fenced as `text` instead of a JSON-encoded string, so line breaks and punctuation are preserved.
- **`bunfig.toml`** — a one-day `minimumReleaseAge` install guard for development.

## Changed

- **Progress failures name their server** — the CLI prefixes each failure line with the server id, since concurrent servers interleave their events.
- **Connection lifetime** — every connection is closed before the report is written, so none remains open when `run()` resolves or rejects.
- **`erasableSyntaxOnly`** — enabled in `tsconfig.json`; `McpReporter` no longer uses a constructor parameter property. No public API change.

## Deprecated

- **`ServerInfo.client`** — never populated, because each connection is closed before its report is rendered. It is marked `@deprecated`; do not read it.
